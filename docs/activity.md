# История команд и аналитика

Страница [/history](http://localhost:8010/history) открывается через меню
«История и аналитика». Данные читаются из PostgreSQL через API, без отдельного
демонстрационного массива на frontend.

## Профиль владельца

Домашний интерфейс записывает команды голоса, текста и кнопок примеров в выбранный
профиль **maksim ivanov**, username **maksim_ivanov**. Это фиксированная привязка,
а не распознавание личности по тембру. Голосовые образцы личности не регистрируются.

app/services/profiles.py создаёт владельца при необходимости. При обновлении
приложения прежний voice_dialogue переименовывается, сохраняя ID и историю.
Если целевой профиль уже существует, к нему переносятся команды только прежнего
общего профиля. Остальные пользователи и их команды остаются у своих владельцев.
Подготовка выполняется в bootstrap и проверяется при создании диалога.

Выбор пользователя в истории — фильтр просмотра. Он не меняет владельца новых
команд помощника. Учебные записи других пользователей остаются доступны в журнале.

## Журнал

По умолчанию: выполненные команды за 30 дней. Доступны пользователь, период,
фаза диалога, поиск по тексту и страницы по 20 записей. Поиск применяется после
кнопки «Найти», обновление — по «Обновить данные» или при входе на страницу.

Запись показывает автора, время создания, исходную команду, намерение, найденные
параметры и результат исполнения. В подробностях доступны ID, вероятность класса,
число уточнений, старый статус команды, operation_id и время записи квитанции.
Время записи команды и результата выводится в часовом поясе браузера.

- **Выполнено**: только dialogue_sessions.phase=executed, получена успешная квитанция.
- **Ошибка исполнения**: исполнитель вернул success=false.
- **Ожидает исполнителя**: пользователь согласовал параметры, квитанции ещё нет.
- **Уточняется / ожидает «да» / отменено / не удалось уточнить**: отдельные фазы.
- **Без квитанции (старый API)**: у команды нет строки dialogue_sessions.
  Даже status=completed не делает такую запись выполненным действием.

Журнал хранит исходную команду и итоговые параметры; это не полная расшифровка
всех реплик разговора. execution_confirmed и execution_message не вычисляются
по наличию параметров: они отражают сохранённый сервером результат исполнителя.

## Метрики

Пользователь и период применяются ко всей странице. Фаза и текст поиска ограничивают
только журнал; карточки остаются сводкой пользователя за выбранный период.

- Всего команд, подтверждённые исполнения, команды в процессе, число по каждой фазе.
- Успех исполнения = executed / (executed + execution_failed). Без полученных
  квитанций значение отсутствует («—»), а не объявляется равным 0% или 100%.
- Среднее количество уточнений берётся из commands.clarifications.
- Частые команды группируются по намерению: число всех команд и число исполненных.
- Для каждого пользователя: число команд и подтверждённых исполнений.
- Динамика по датам: число команд и исполнений среди команд, созданных в этот день.
  Это даты создания команд, а не отдельный календарь получения квитанций.

Границы периода определяются по календарным дням UTC, включая сегодня. Временная
зона PostgreSQL в используемом Docker-окружении — UTC; в таблице по дням это указано.
Метрики не являются оценкой точности ASR/NLU. Сводка нескольких запросов не обещает
атомарный снимок при одновременной записи другими клиентами; обновите страницу данных.

## API

    GET /api/activity?user_id=4&phase=executed&days=30&limit=20&offset=0
    GET /api/analytics/activity?user_id=4&days=30
    GET /api/users

Все фильтры необязательные; без days — всё время, без user_id — все пользователи.
phase принимает фазы диалога и legacy. search ищет подстроку исходной команды:
символы % и _ трактуются буквально. limit 1–100, offset ≥ 0, days 1–365,
search до 300 символов. Некорректные значения дают 422; пустая выборка — 200.
Оба новых маршрута только читают данные, не вызывают исполнителей.

## Где смотреть код

1. app/schemas/activity.py — поля журнала и сводки.
2. app/repositories/activity.py — LEFT JOIN к диалогу, фильтры, COUNT/SUM/AVG/GROUP BY.
3. app/services/activity.py — преобразование БД в ответ API.
4. app/api/activity.py — маршруты и валидация параметров.
5. frontend/src/features/activity — загрузка, фильтры, таблица и визуализация метрик.
6. frontend/src/widgets/activity — сборка функций в панель.
7. frontend/src/pages/history — страница; app/model/useNavigation.js — меню и Back/Forward.

Запоздавшие ответы фильтров игнорируются; предыдущие запросы отменяются через
AbortController. Состояние помощника живёт на уровне App, поэтому переход между
помощником и историей не сбрасывает будильник. На странице истории отображается
сигнал с кнопкой остановки; голосовые Alt+M/Alt+R работают на странице помощника.
Escape останавливает речь и микрофон на обеих страницах.

Проверки: tests/test_profiles.py, tests/test_activity.py и проверки навигации,
фильтров и сигнала в настоящих Chrome/Firefox. Итоги — [verification.md](verification.md).
