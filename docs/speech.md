# Голосовой ввод в Firefox

Firefox использует локальный резервный путь: getUserMedia → AudioWorklet → WAV PCM
16 кГц, моно, 16 бит → POST /api/speech/transcribe → Vosk → обычный API диалога.
В браузере не нужно включать экспериментальные флаги SpeechRecognition.
Chrome/Edge продолжают использовать свой SpeechRecognition, когда он доступен.

В Docker модель устанавливается автоматически во время сборки. После загрузки образа
распознавание Firefox не требует стороннего API, ключа или внешней сети. При первой
сборке нужен интернет для Python-пакетов и модели (архив около 45 МБ).
Для микрофона нужен localhost или HTTPS и разрешение пользователя.

## Локальный Python

После установки requirements.txt выполните:

    python -m app.speech.prepare

По умолчанию модель находится в data/models/vosk-model-small-ru-0.22.
Путь можно задать через SPEECH_MODEL_PATH. Модели исключены из Git и Docker build
context; в образе используется /opt/models/vosk-model-small-ru-0.22.

Модель: vosk-model-small-ru-0.22, Apache 2.0 по
[официальному списку Vosk](https://alphacephei.com/vosk/models).
[Архив](https://alphacephei.com/vosk/models/vosk-model-small-ru-0.22.zip)
проверяется по SHA-256:
961d5ff98a17f4aa6de69864d0aa71fa5bac682301d2b5d17a3f24c5c99a46d4.

MASSIVE остаётся текстовым датасетом намерений. Vosk — отдельная готовая акустическая
модель; она не обучалась на MASSIVE в рамках проекта.

## Поведение клиента

Микрофон включается только по кнопке или Alt+M. Пауза после фразы около 1,1 секунды
завершает запись. Максимальная длительность — 20 секунд; после 8 секунд без речи
помощник предлагает повторить. Во время озвучивания микрофон не слушает.
Escape и кнопка «Пауза» освобождают микрофон и отменяют ожидающий запрос.

API принимает ограниченную короткую WAV-запись. Долгая, повреждённая или неподходящая
запись даёт 400; отсутствие модели — 503. GET /api/speech/status сообщает готовность.
Записи не сохраняются после обработки; модель загружается в память один раз.
TTS и скорость чтения по-прежнему обеспечиваются браузером и установленными голосами ОС.

## Проверка

В настоящем Firefox 158 через Playwright проверена цепочка с реальным AudioWorklet,
ресемплированием и сервером Vosk. Микрофон заменён потоком трёх синтетических фраз:
«Поставь будильник», «На семь утра», «Да». Запись дошла до ready с проговариванием
параметров и без ложного сообщения об исполнении. TTS в автоматическом тесте имитируется.
Проверены отказ разрешения, остановка Escape и отсутствие горизонтального переполнения.

WAV-примеры tests/fixtures/audio созданы локально голосом Microsoft Irina Desktop
через Windows Speech API; это синтетическая речь, а не записи пользователей.
Результат на трёх образцах не является оценкой WER или доказательством качества
на живой речи и шумном микрофоне. Для этого нужны отдельные испытания на устройстве.

Проверка API вручную (в PowerShell используйте curl.exe вместо curl):

    curl -F "audio=@tests/fixtures/audio/alarm.wav" http://localhost:8010/api/speech/transcribe

## React-модули

UI расположен в frontend/src/features/voice/ui, ASR/TTS — в features/voice/model/VoiceSession.js,
запись WAV — в features/voice/lib. Widget assistant связывает эти модули с API диалога.
После отменённой или завершённой команды «Говорить» сбрасывает старую сессию и начинает новую запись.
Формы «семь часов десять минут» и «7 часов 10 минут» сохраняются целиком; часы и минуты проверяются по диапазону.

Кнопка «Новая команда» доступна сразу и после одного приглашения автоматически включает запись. Повторно нажимать «Говорить» не требуется. При новом диалоге старые ответы восстановления и polling игнорируются.
