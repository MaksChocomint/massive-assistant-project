# Работающие примеры команд

Основной диалог остаётся сервисом уточнения и согласования. Для демонстрации
веб-клиент выполняет роль отдельного исполнителя: управляет состоянием вкладки
и возвращает результат серверу. База и контракт квитанций не изменялись.

## Как проверить

1. Откройте приложение и скажите «Поставь будильник через минуту» либо нажмите
   одноимённую кнопку справа. Можно также начать с «Поставь будильник» и на
   уточнение ответить «Через минуту».
2. До ответа «да» отсчёт отсутствует. После согласия справа появляется таймер,
   а результат для интеграции содержит execution_confirmed=true и сообщение
   об установленном будильнике. Отсчёт начинается в момент исполнения после «да».
3. По истечении минуты звучит повторяющийся сигнал. Нажмите «Остановить сигнал».
   До срабатывания эта же кнопка отменяет будильник.
4. «Выключи свет» → «да» меняет фон на тёмный, «Включи свет» → «да» возвращает
   светлый фон. Каждый результат записывается отдельной квитанцией.
5. «Какой сегодня день и сколько времени» → «да» возвращает дату, день недели
   и время устройства с секундами. Включённое озвучивание читает этот результат.

Новая команда не отменяет уже установленный будильник. Отмена будильника справа
удаляет его из локального расписания; квитанция исходной установки остаётся
историческим фактом. Это не изменение результата исходной операции установки.

## Путь исполнения

    Голос / текст / кнопка примера
      → POST /api/dialogues → уточнения → проговаривание → «да»
      → ready → BrowserExecutor.execute
      → реальное действие адаптера → квитанция
      → POST /api/dialogues/{id}/execution → ответ сервера → озвучивание

Реестр в frontend/src/features/browser-executor/model/adapters.js поддерживает
alarm_set, iot_hue_lighton, iot_hue_lightoff и datetime_query. Виджет assistant
соединяет исполнителя с API, не создавая зависимостей между соседними features.

Для успешной операции сервер выставляет phase=executed, execution_confirmed=true
и execution_message из квитанции. При ошибке действия отправляется success=false:
phase=execution_failed, execution_confirmed=false, сообщение содержит причину.
При недоступном API клиент не подменяет флаг успеха: повторяет сохранённую
квитанцию после восстановления связи. Срок будильника при повторе не сдвигается.
operation_id имеет вид browser-{id диалога}. Серверная идемпотентность сохраняется.

## Время, хранение и ограничения

- Будильник: «через минуту», «через одну минуту», «через 10 секунд», «через
  полчаса», «на минуту вперёд», «07:10», «семь часов десять минут», «семь утра».
  Время в прошлом означает ближайший следующий такой момент — завтра.
  Парсер принимает ограниченную русскую грамматику, не произвольные формулировки.
- Относительный срок вычисляется от момента исполнения; абсолютное время и
  дата/время используют локальный часовой пояс устройства пользователя.
- Счётчик вычисляется по абсолютному сроку, а не уменьшением числа раз в секунду.
  Фоновая вкладка, сон компьютера и ограничения браузера могут задержать сигнал.
  Если вкладка снова активна после срока, будильник срабатывает при следующем tick.
- Фон, сроки и квитанции сохраняются в sessionStorage одной вкладки. После
  перезагрузки состояние восстанавливается, но браузер может потребовать жест
  для звука: нажмите «Включить звук будильника». Закрытая вкладка не сигналит.
- Без работающего AudioContext установка будильника возвращает ошибку, а не
  обещание сигнала. Даже открытый AudioContext не проверяет громкость колонок
  и системное выключение звука. Системный будильник и физическая лампа не управляются.
- Для других намерений MASSIVE браузерного адаптера нет: они остаются в ready
  до квитанции внешней системы. Доступность намерения в датасете не означает
  наличие его исполнителя.

## NLU и расширение

Для простых явных «включи свет» и «выключи свет» добавлено узкое правило выбора
между близкими классами освещения после ML-классификатора. Оно не переписывает
«сделай свет ярче» и отрицания. Вероятность остаётся вероятностью выбранного
класса модели; гарантией точности она не является. Исходный датасет не изменён.

Новый адаптер добавляется в реестр и получает только нужные функции окружения.
Он должен вернуть сообщение после проверенного эффекта либо выбросить ошибку.
Для действий вне браузера нужны собственные гарантии доставки, авторизация
исполнителя и дедупликация на стороне целевой системы. sessionStorage не даёт
гарантии exactly-once при аварии страницы между эффектом и сохранением квитанции.

Тесты: frontend/test/browser-executor.test.js проверяет сроки, сигнал, отсутствие
повторного эффекта, ошибку звука, ожидание согласия и серверные поля результата.
tests/test_services.py и tests/test_dialogue.py проверяют новые форматы времени
и разграничение команд света. Документация Web Audio: [AudioContext](https://developer.mozilla.org/en-US/docs/Web/API/AudioContext).
