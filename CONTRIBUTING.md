# Работа с Git и GitHub

Репозиторий: https://github.com/MaksChocomint/massive-assistant-project

В main находится опубликованная рабочая версия. Изменения разрабатываются в отдельных
ветках и предлагаются через Pull Request. Это личный проект: слияние требует успешных
проверок CI, внешнее одобрение не обязательно. Автор просматривает diff и результаты
проверок, затем может самостоятельно объединить PR.

## Получить проект

```bash
git clone https://github.com/MaksChocomint/massive-assistant-project.git
cd massive-assistant-project
```

Запуск приложения и установка зависимостей описаны в [README](README.md).
Для существующей рабочей копии origin уже подключён; заново выполнять git init не нужно.

## Начать изменение

Рабочая копия должна быть чистой; незавершённую работу сначала зафиксируйте в своей ветке.

```bash
git switch main
git pull --ff-only
git switch -c feat/short-description
```

Используйте префиксы feat/, fix/, docs/ или chore/. Коммиты называйте по результату:
feat: add …, fix: handle …, test: cover …, docs: explain …, ci: check … .
Не переписывайте уже опубликованную историю общей ветки.

## Проверить и отправить

```bash
python -m ruff check .
python -m ruff format --check .
python -m pytest
node --check app/static/app.js
node --check app/static/presentation.js
git diff --check
git status --short
git add -- path/to/changed-file
git diff --cached
git commit -m "feat: describe the resulting behavior"
git push -u origin HEAD
```

Выберите конкретные изменённые файлы вместо path/to/changed-file. Просматривайте staged
diff до коммита. .env, окружение Python, логи, покрытие и временные снимки исключены
из Git. Презентация и итоговая ER-диаграмма включены в репозиторий.
.gitattributes обеспечивает LF для исходников и сохраняет бинарные файлы без преобразования.

## Открыть Pull Request

На GitHub откройте Compare & pull request для отправленной ветки, выберите base: main.
Заполните шаблон: проблема, результат изменения и шаги проверки. Не запрашивайте слияние,
пока CI красный. После замечаний исправляйте код отдельными коммитами и отвечайте в тредах.

Обязательные проверки: lint, test, migrations, frontend и docker. Test проверяет покрытие
не ниже 70%; migrations применяет и откатывает Alembic; docker запускает приложение с БД.
Новый push может отменить предыдущую проверку той же ветки; проверять нужно последний SHA.

Если ветка отстала от main, обновите её обычным merge и снова запустите проверки:

```bash
git fetch origin
git merge origin/main
git push
```

После просмотра изменений и зелёного CI выполните Merge на GitHub. Затем обновите локальную main.

## Если потребуется учебное code review

- Минимум 3 настоящих PR с описанием изменений.
- Получить ревью минимум на 2 своих PR и провести ревью минимум 2 PR коллеги.
- В каждом проверяемом PR — не менее 3 содержательных замечаний; ответы и исправления
  должны оставаться видимыми в GitHub.
- Добавление одногруппника как collaborator и запрос ревью выполняются для конкретного
  согласованного участника. Автоматические проверки не являются студенческим code review.

Первичная публикация проекта содержит накопленную историю разработки. Она не выдаётся
за PR, прошедшие взаимное ревью. Число коммитов не подменяет число PR и полученных отзывов.
